# Contributing

Thanks for your interest in SudarshanTechLabs projects. These are solo-maintained, so
small, focused contributions are the easiest to review and merge.

## Before you start

- **Security issues:** do not open a public issue. Follow [SECURITY.md](SECURITY.md).
- **Bugs and ideas:** open an issue first using the bug or feature template, so we can
  agree on the change before you write code.
- Check open issues and pull requests to avoid duplicate work.

## Pull requests

1. Fork the repository and create a branch from `main` (e.g. `fix/short-description`).
2. Keep one change per pull request. Unrelated fixes go in separate PRs.
3. Follow the existing code style. Run the project's tests and linters before pushing.
4. Use a clear title in the form `type: short description`
   (`fix`, `feat`, `docs`, `chore`, `ci`, `refactor`, `test`).
5. Fill in the pull request template, including `Fixes #<issue>` and the self-review checklist.
